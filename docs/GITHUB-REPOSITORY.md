This document describes the LatticeVale **v14.6.8** repository/release contract for GitHub.

## Repository structure

- Keep the project root named `Lattice-Vale` in distributed ZIP archives.
- Keep `README.md` and `LICENSE` in the repository root.
- Current contribution/security/support guidance lives in `docs/CONTRIBUTING.md`, `docs/SECURITY.md`, and `docs/SUPPORT.md`; GitHub recognizes these supported community-health locations.
- Issue templates and pull-request metadata live under `.github/`.
- Historical v13 patch notes remain in Git but are repository-only under `LatticeVale-Core/release/release-content.json` and are excluded from normal end-user release archives.

## GitHub size and path compatibility

LatticeVale release validation requires every regular repository file to remain below GitHub's 100 MiB hard single-file limit. Paths must be portable across Windows/Linux: no absolute paths, traversal segments, reserved Windows device names, invalid control characters, reparse points, or generated bytecode/cache artifacts.

The project remains intentionally source-only: no `.exe`, `.msi`, `.dll`, `.deb`, `.rpm`, `.zip`, `.7z`, model weights, container-image archives, credentials, backups, or machine-generated runtime state are committed as release source.

## Full release ZIP

The publishable full release must:

1. contain exactly one top-level directory, `Lattice-Vale/`;
2. include exactly the files allowed by the declarative release-content policy plus `installer/SOURCE-SHA256SUMS.txt`;
3. exclude repository-only historical archives and generated/private state;
4. pass CRC validation;
5. match the source manifest; and
6. compare byte-for-byte with the qualified release tree for every included member.

## Pre-publication checks

Before publishing v14.6.7:

- version/schema/policy/fixture-count documentation must agree with source;
- all 151 deterministic fixtures across the six current shards and both resume simulations must pass in their supported environments;
- the inherited v14.6.5 Matrix/Tailscale identity preservation, external reachability, and managed gateway-migration requirements must remain satisfied; v14.6.6 additionally verifies the bounded resource controller, overlay ownership, and static-to-dynamic resource-policy reconciliation; gateway migration recovery must accept nonzero Hermes results only when fresh state, the matching default s6 PID, and the expected managed-profile set prove convergence;
- Bash/Python/static checks and Windows PowerShell parse/manifest checks must pass in CI; use the documented isolated Windows PowerShell verifier (`powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\installer\verify-release.ps1`) from the `Lattice-Vale` root;
- `installer/SOURCE-SHA256SUMS.txt` must be regenerated after the final source/documentation change;
- both ZIPs must have the required `Lattice-Vale/` root, valid CRCs, portable paths, no duplicate/case-colliding members, and byte-for-byte source equivalence; and
- no individual repository file may exceed 100 MiB.

The current full release is built from the qualified `main` commit. The `14.6.7` tag must identify that exact commit before publication; do not publish a ZIP against an older tag target.

GitHub's community-health checklist is a recommendation rather than a special LatticeVale runtime requirement. LatticeVale keeps its existing README, MIT license, contribution, security, support, issue-template, pull-request, and CI metadata synchronized so repository users receive current guidance.
