# LatticeVale v14.7.0 review: conservative source improvements

Baseline GitHub `main`: `71ca6d940ad990b1a0e89cf7e3436bed370c14e3` (`14.7.0 Release`, 2026-11-21). Review changes are based on the recorded `main` release source. All edits were performed offline; no temporary review workflows or review branches are part of this patch.

## Implemented changes and changed behavior

- **Function index:** deterministic Python regeneration and `--check`; current line numbers/function declarations are documented and an executable staleness regression detects drift. No installer logic changes. Existing installations: no change.
- **Live qualification:** atomic failed-step JSON after valid arguments, per-project `docker compose` sampling/log reads, explicit health-based `passCriteria`. Existing verdict logic is unchanged; pressure/watchdog values remain advisory. Runs only with exact disposable marker. Existing installations: no change; opt-in test-tool behavior only.
- **Read-only restore inspection:** `./manage.sh restore BACKUP-DIR --plan` (also default when the directory is supplied) checks archive, schema/options metadata, and optional PostgreSQL dumps, then lists prospective replaced files. No apply mode and no data mutation. Existing installations: new inspection command only. It requires readable active installation metadata and the `pg_restore` client.
- **Manual backup verification:** adds `pg_restore --list` on custom-format database dumps, archive `tar -tzf`, elapsed/downtime reporting and an explicit consistency warning; includes user Compose override and Tailscale state when present. Existing installations: backups can now refuse previously accepted malformed dumps/archives; persistent user data is not changed.
- **Pre-update backup:** free-space preflight before stopping services, plus measured service-stop window. It intentionally **does not** exclude model blobs, caches or any user data without proven safe exclusion. Existing installations: inadequate free space now rejects backup earlier; the same preexisting installer per-run skip remains available. No additional service is stopped.
- **DirectML HTTP gateway:** reject over-context requests with HTTP 400 OpenAI-style `context_length_exceeded` instead of silently discarding recent input; opt-in constant-time bearer authorization with `/health` exemption; 30-second request read timeout; at most 8 simultaneous HTTP handlers, excess returns 503. Sampling/stop behavior unchanged. Existing installations: overlong prompts that previously returned truncated responses now fail explicitly; default auth is off, and high-concurrency/slow-client traffic may receive 503/timeouts. Actual Hermes retry handling must be tested.

## Not implemented because safety or platform evidence is missing

- Release workflow permissions/publish separation, immutable published assets, deterministic PowerShell ZIP generation and dual-build comparison, semver tag trigger, artifact attestation: these require PowerShell and/or new GitHub Actions verification. No release-workflow weakening was made; current release artifacts should **not** be called byte-reproducible based on this work.
- Consolidation of 106 legacy fixture version allowlists, README/patch-note historical extraction, high-blast-radius uninstaller and network mock coverage: deferred to avoid wide mechanical changes without a reliable Windows test pass.
- Model/cache exclusion from backup, automatic data restoration, full container-hardening defaults, read-only Hermes vault mode, multistage QMD image: intentionally not changed without verified ownership, workload compatibility, and explicit approval for restore execution.
- DB `not-configured` sentinel runtime reporting, Honcho tag-retarget enforcement, official Docker/NVIDIA apt signing fingerprints: not changed without source-specific runtime proof/verified authoritative fingerprints. **Do not invent fingerprints.**

## Proposals for a separate opt-in live-test branch (no code changes)

- **Compose:** begin with a single disposable service override using `security_opt: [no-new-privileges:true]`, `cap_drop: [ALL]`, and a measured low-but-sufficient `pids_limit`; validate service startup, readiness, DB initialization/migration, network access, file permissions and Hermes subprocess execution. Do not propagate to all twelve containers without per-service testing. Keep user `compose.override.yaml` under user ownership.
- **Vault:** evaluate a read-only Obsidian vault mount with a separate writable ingestion inbox; test QMD indexing, Hermes edits, sync software, approvals and recovery. The default writable mount remains unchanged.
- **QMD:** investigate multi-stage image pinning; test native package availability, npm module path, binary compatibility, model cache persistence, image builds with clean/offline conditions, image size and runtime health. Do not flip `@latest` until there is a compatible pinned artifact and rollback.

## Required verification before committing/releasing

1. Apply only the changed-file overlay to the **same `main` snapshot** above and inspect the GitHub Desktop diff. Reject unexpected deletions or case-insensitive path collisions.
2. In Windows PowerShell 5.1 or 7 at repository root: `./tools/New-SourceManifest.ps1` (Windows uses `\` separators equivalently); then `./installer/verify-release.ps1`. The manifest **must be regenerated** after merging: it is intentionally not included in the changed-files overlay because only the project's PowerShell generator is authorized. The changed/new release files must be hashed under `installer/SOURCE-SHA256SUMS.txt` before CI can attest source integrity.
3. Run `bash -n` on changed shell scripts, Python compilation, `python LatticeVale-Core/tests/static-audit.py`, `python LatticeVale-Core/tests/run-regressions.py`, `python LatticeVale-Core/tests/minimal-resume-simulation.py` and `python LatticeVale-Core/tests/interruption-resume-simulation.py` in the expected CI environment. Verify all **154/154** and both resume simulations, then run the official GitHub Actions checks on a branch.
4. On disposable Windows/WSL: PowerShell 5.1 and 7 parsing, Option 1 Resume / repair, the read-only `restore --plan` on both genuine backup types, PostgreSQL dump compatibility, backup free-space refusal before stopping, observed stop/start time, DirectML real-GPU model request and context overflow, Hermes treatment of HTTP 400/401/503, behavior under client disconnect and concurrent requests, and manually marked live qualification with report failure path and composed service isolation. Preserve current WSL distro/VHDX, secrets, `compose.override.yaml`, native Windows Tailscale/Ollama and user data.

This is a source-level overlay and not a production-certified release. No runtime claims are made without corresponding end-to-end evidence.
